# RadicalMart Bug Tracker

Публичный баг-трекер для ошибок, предложений и замечаний по продуктам экосистемы RadicalMart.

Этот репозиторий не содержит исходный код. Он нужен для учета обращений: багов, идей, проблем совместимости, замечаний по интерфейсу, локализации и документации.

## Перед созданием issue

Пожалуйста, сначала проверьте открытые и закрытые issue. Возможно, такая тема уже есть.

Если по нужному продукту или версии открыт общий issue, пишите комментарий туда. Так обсуждение не расползается по десяткам отдельных задач, а все замечания остаются в одном месте.

## RadicalMart Express / RME-UIkit

По RadicalMart Express планируется полная переработка v4, поэтому старые отдельные issue по RME/RME-UIkit могут быть объединены в один общий issue.

Если у вас есть баги, замечания или предложения по RadicalMart Express / RME-UIkit, пожалуйста, добавляйте их в общий issue по RME v4, если он открыт. Новые отдельные issue по RME/RME-UIkit пока лучше не создавать.

## Что можно писать

- ошибки в работе компонентов, плагинов, модулей и шаблонов;
- проблемы совместимости с Joomla, PHP, шаблонами или сторонними расширениями;
- ошибки верстки, интерфейса и адаптивности;
- пропущенные языковые строки и ошибки локализации;
- предложения по улучшению поведения или настроек;
- замечания и дополнения к документации.

## Что не стоит публиковать

- пароли, токены, ключи API и персональные данные;
- доступы к сайтам и приватные ссылки;
- публичные инструкции по эксплуатации уязвимостей;
- дубли уже открытых issue.

Если проблема связана с безопасностью или приватными данными, не публикуйте детали открыто. Используйте личный канал связи с командой проекта.

## Как оформить баг

Желательно указать:

- продукт: RadicalMart, RME, RM-UIkit, RME-UIkit, плагин, модуль и т.д.;
- версии Joomla, PHP и RadicalMart/RME;
- что делали пошагово;
- что ожидали получить;
- что произошло фактически;
- текст ошибки, если он есть;
- скриншоты или короткое видео, если проблема визуальная;
- дополнительный контекст: шаблон, сторонние расширения, мультиязычность, ЧПУ и т.п.

Пример:

~~~md
## Окружение

- Joomla:
- PHP:
- RadicalMart / RME:
- Шаблон:

## Что делаю

1.
2.
3.

## Ожидаю

...

## Получаю

...

## Дополнительно

Скриншот, лог ошибки или ссылка на связанный issue.
~~~

## Как оформить предложение

~~~md
## Проблема

Сейчас неудобно / невозможно / легко ошибиться при ...

## Предложение

Добавить / изменить / вынести в настройку ...

## Зачем это нужно

Это поможет ...
~~~

## Префиксы в заголовках

Используйте короткий префикс в начале заголовка, чтобы issue было проще сортировать.

| Префикс | Для чего |
| --- | --- |
| `[RM]` | RadicalMart |
| `[RME]` | RadicalMart Express |
| `[RM-UIkit]` | шаблон RadicalMart UIkit |
| `[RME-UIkit]` | шаблон RadicalMart Express UIkit |
| `[DOC]` | документация |
| `[Plugin]` | плагины и интеграции |

Пример:

~~~md
[RME] Не применяется настройка количества в заказе
~~~

## Как обрабатываются issue

Похожие обращения могут быть объединены. Старые issue могут закрываться как дубли или как перенесенные в общий issue по версии/направлению.

Если issue закрыт как объединенный, это не значит, что замечание проигнорировано. Это значит, что дальнейшая проверка или обсуждение ведется в другом, более общем issue.
